# RoboPico calibration checkpoint (updated 2026-11-04)

To reproduce the USB wheel or line test on this robot, copy the profile from the repository root before building:

    Copy-Item calibration/robot_config.local.h app_program/robot_config.local.h

Keep any existing local overrides before replacing that file. Build the IRMotorScan or IRLineTrace profile. The settings apply only to those two bench profiles. The reviewed copy under calibration belongs on Git; the active per-checkout copy and config/wifi_secrets.h are ignored. Put subsequent measured changes in the reviewed copy and sync it to the active copy.

- Wheel geometry: 1,889 left and 1,894 right counts over three revolutions. Use 631 counts/rev, 220 mm rollout and 113 mm tyre-centre spacing.
- Straight-drive baseline: left/right trim 73/98, PID Kp/Ki/Kd 30/10/0 (milli units), 20% output cap. Target was 375 counts/s; the Ki-10 floor run recorded 265 left and 274 right in the final second. Speed calibration is unfinished.
- Line following: latest firmware applies a further 990/1000 to the right PWM after PID rounding. This is a trial value; short passes did not establish an improvement over 995/1000. The motor and line tests use a 200 mm forward clearance threshold. Intermittent echoes can stop a run.
- IR endpoints (right, left, barcode) remain in app_program/robot_ir_calibration.h: white 187/189/197, black 3214/3177/2472. Barcode capture and replay are next: GP28 saw contrast but the A sweeps were incomplete. Check one narrow bar and its neighbouring white gap first.
- IMU timing (2026-11-04): a 10 ms cyclic service wake replaces the relative sleep that effectively serviced the 50 Hz accelerometer about every 30 ms. The stationary sensor-only recheck recorded zero overruns over a 28.35 s counter window, with no sensor I/O or publication errors. Sensor configuration and validity/overrun rejection are unchanged; timing under the full integrated workload remains to be checked.
- IMU mounting: `BOARD_S4_MOUNTING=1` maps this car's forward/left/up to sensor -Y/+X/+Z. Processed pitch is positive nose-up and roll positive left-side-up; raw XYZ telemetry retains the sensor axes. This handling is implemented and software-tested, but its diagnostic image has not been flashed. Profile 0 remains the default; the motor/line profile above does not select a Buddy 4 mounting profile.
- Terrain calibration: no flat-reference offsets or accelerometer bias/scale corrections have been accepted. Keep `BOARD_TERRAIN_CALIBRATED=0` and `BOARD_ACCEL_CALIBRATED=0`; zero bias and gain 1000 are nominal placeholders. Measured corrections use `BOARD_ACCEL_BIAS_{X,Y,Z}_MG` and `BOARD_ACCEL_GAIN_{X,Y,Z}_MILLI` before body-axis mapping. The latest stationary run averaged about 962 mg, and earlier isolated readings below 800 mg remain unexplained. Next verify posture signs, flat-return repeatability and angle accuracy. Terrain, autonomous bypass and PID calibration are not signed off.
- One-sided height: the new software model reports IMU rise while the opposite drive wheel remains on level floor. Measure tyre-centre track width and the IMU centre's forward/left/up offsets from the drive-axle centre; up is measured above the axle, not the floor. Fill `BOARD_TRACK_WIDTH_MM` and `BOARD_IMU_{FORWARD,LEFT,UP}_MM`, then verify before setting `BOARD_IMU_GEOMETRY_CALIBRATED=1`. `BOARD_TERRAIN_ONE_SIDED=1` is the default; missing geometry leaves height invalid. Validate both sides against independently measured IMU rise; ramp-surface height is a different quantity.
- Motion/reporting: classification, encoder-estimated turn rate, retained impact candidates and events since reset are implemented for software testing. These thresholds are engineering defaults awaiting driving tests. The existing height telemetry is unchanged; an additional 73-bit/10-byte message on `Robopico/sensors/buddy4/motion/v1` feeds the updated dashboard. Verify actual Vehicle Controller, Buddy 1 and MQTT delivery and integrated timing on the car. A high-g candidate does not prove a collision, and encoder estimates require checking for wheel slip.
- Magnetometer reported valid XYZ samples. Original vs returned orientation differed, so no compass-heading offsets have been accepted. Magnetic assistance for recovery remains unvalidated.
